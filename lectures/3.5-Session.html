1. Deliberately Similar

cities = [
  'San Francisco',
  'London',
  'Paris',
  'Beijing']

# Prints London
print(cities[2])
  1. San Francisco
  2. London
  3. Paris
  4. IndexError

Answer: 3. Indexes start at 0. And the comment is wrong: it’s copied from my own slide in Dictionaries.

From Dictionaries (“Deliberately Similar”). The point: a comment is context, and context can be wrong. Hold on to that for the readings.

Story (≤ 60 seconds): zebras relabelled as finches, which is why a dictionary key has to be immutable.

3. Find the 5

my_list = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]

Which prints 5?

  1. my_list[1][1]
  2. my_list[2][2]
  3. my_list[1,1]
  4. my_list[4]

Answer: 1. Row 1, column 1, counting from zero. (2 gives 9; 3 is a TypeError; 4 is an IndexError.)

What’s the Key?

Reports or Events?

stories = [('BBC','Chibok'), ('CNN','Chibok'),
           ('Japan Times','Chibok'), ('SaharaReporters','Chibok')]

counts = {}
for outlet, event in stories:
  counts[event] = counts.get(event, 0) + 1

print(len(stories))
print(counts)
4
{'Chibok': 4}

Four kidnappings, or one kidnapping reported four times?

Illustrative data, not GDELT’s: the outlets are the ones that D’Ignazio and Klein name on p.2.

Same data, two keys. Count by story and you get 4; count by event and you get 1. Remember from Dictionaries: “the key is unique. Always.” The choice of key is the choice of what you’re counting.

The Numbers Don’t Speak for Themselves

On my slide Actually
London longitude 0.1275 -0.1275
New York longitude 74.0059 -74.0059
Tokyo time zone +8 +9
New York time zone -5 -5 (winter), -4 (summer)

“‘Raw data’ is an oxymoron” ~ Gitelman and Jackson, quoted in D’Ignazio and Klein (2020, 13)

These numbers have been in my videos for years. Nobody spotted them, because numbers on a slide look authoritative. Those who did spot them had context: they know where New York is.

The New York time zone isn’t even wrong: it’s incomplete. The structure has nowhere to say “when”.

A Data Dictionary

If you are lucky you might get a paragraph about where the data are from or a data dictionary that describes what each column in a particular spreadsheet means. ~ D’Ignazio and Klein (2020, 6)

ds2 = {
  'lat': [...], 'lon': [...], 'tz': [...], 'name': [...]
}

In ds2, the keys are the only metadata. Is tz in hours? Is it summer time?

The pun is the point: a Python dictionary’s keys are a (very thin) data dictionary.

Break It, Then Fix It

Break It

git rm fileA.md
git commit -m "Removed file."
ls                       # fileA.md has gone
git log --oneline        # find the hash before the removal
git checkout <hash>
ls                       # fileA.md is back

Live, in the SDS container: the Recovery slide from the Git video, done for real. Set up the repo beforehand (README → fileA.md → commit, as in the video).

Ask before running git checkout: “What will git status say now?”

Detached HEAD

git status               # HEAD detached at <hash>
git switch -             # back to the branch you were on

To bring one file back into the present:

git restore --source=<hash> fileA.md
git commit -m "Restored fileA.md"

This is the “getting back to HEAD” discussion that the Git video promises but never delivers.

git switch - works whether your branch is main or master. GitHub now defaults to main, but the video slides say master.

Pull, Then Push

git pull                 # get any changes from GitHub first
git add <notebook.ipynb>
git commit -m "What I did, and why"
git push                 # only now are you backed up

When asked for a password, GitHub wants a personal access token (or an SSH key), not your account password.

The video’s workflow slide leaves out pull, but the learning outcome includes it.

Authentication is the gap: “Before class” asked students to check they could log in, but nothing teaches it. Point to the practical’s instructions. [CHECK: how the practical sets up authentication]

Spare question if time: “You commit, and then your laptop is stolen. Is your work on GitHub?” (No: all changes are local until pushed.) Story: the flatmate’s laptop.

A Commit Message Is Context

The way through this predicament is by considering context, a process that includes understanding the provenance and environment from which the data was collected […] ~ D’Ignazio and Klein (2020, 27)

git log is the provenance of your work. Write the message for the person who will read it in six months.

Bridge to the practical: the final commit of the notebook. Ask for a message that would make sense to a stranger.
